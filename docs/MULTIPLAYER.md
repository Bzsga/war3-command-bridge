# 多人接入

当前运行器附带单人演示和可复用启动组件；没有地图业务相关的双人用例。多人接入由目标地图定义槽位、玩家状态与同步路径。

运行器的 `lan_support.classic_metadata`、宿主自动开始人数和 `war3_bridge._launch` 就绪条件都按单人演示设置。接入多人时三处必须一起调整；只增加游戏进程或修改人数不足以完成接入。

## 启动与实例隔离

- 从实际地图配置读取槽位/队伍，设置正确开局人数；不要沿用演示的Player(0)单真人假设。
- 同一宿主按顺序启动客户端，每位使用自己的原生创建方、临时名字和IPC子目录。确认加入正确房间，再启动下一位。
- 保留原始注册表值及类型，读取配置后恢复。原创建方只关闭自己保留句柄对应的游戏。
- 使用 `owned_network.udp_ports(pid)` 检查实际接收端。同机客户端共用UDP6112时，`replay_destination`可选择127.255.255.255回环广播；发送前必须验证本会话GAMEINFO。

这些组件解决本机会话问题，不承诺远端网络隔离或所有安装都具有相同行为。

## 操作与验证

本地命令通过正式同步入口修改世界，本地快照只读状态。需要创建group、timer或其他世界句柄的查询，先在同步域更新缓存。只有真实支持的安装才使用jass.code固定函数调用。

开局验证期望人数、不同本地玩家身份、共同session/build和游戏线程响应。后续人数变化按地图的离队规则处理，不用开局人数硬性阻止剩余玩家。

代表检查：独立选择、单人准备不能提前开战、共同阶段推进、并发资源操作、重复请求、真实离队及继续操作。主机出现desync即失败，不能由两个相同快照抵消。

# 文件协议

## 身份与操作

每局使用新的 `session`、`build` 和 IPC 目录。握手必须匹配当前版本，不使用旧缓存证明新会话可用。

```json
{"session":"<本局身份>","id":"<请求ID>","op":"snapshot"}
```

响应携带 `session`、`build`、`id`、`ok`、`result` 和 `replayed`。同ID同内容重放返回已保存结果，同ID不同内容拒绝。演示操作为 `ping`、`snapshot`、`prepare`、`order`、`reset`；自己的地图另定义固定业务操作。

`request.json`/`response.json` 是完整载荷，`.ready`文件标识传输序号。写入完成后再发布序号，调用者验证响应序号和身份。不要覆盖仍在途的请求。

## 两种序号

| 序号 | 含义 |
|---|---|
| 传输序号 | 区分本次文件交换和旧响应 |
| 请求ID | 业务去重及重复响应 |

多人客户端自己的发送计数不要求相等；同步业务标识与结果根据地图契约校验。

## 错误与边界

分开记录预检、启动、接入、业务、条件和清理失败。超时不表示未执行。响应编码失败也返回明确错误和已知请求身份；操作可能已经执行，不能换ID重做。

JSON编码器使用显式数组标记。遵循字段定义处理nil/空数组/零值，避免换接入层后悄悄改变快照结构。外部JSON只提供数据，不承载执行代码。

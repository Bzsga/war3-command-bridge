# 按阶段排查

| 停在哪一步 | 先核对 |
|---|---|
| 环境预检 | 实际目录、版本、组件、独立模板、可交互桌面 |
| 房间发现 | 本会话名字/端口、竞争进程、捕获socket是否已释放 |
| 入房 | 所属PID/HWND、原生回执nonce、实际UDP接收端、主机加入日志 |
| 载图 | 本局候选与宿主配置、客户端文件大小/CRC视图 |
| 握手 | 新session/build、实例IPC、初始化错误、真正的计时器响应 |
| 业务 | 控件/操作是否可用、异步结算、是否已被自动默认处理推进 |
| 多人不同步 | 无命令对照、本地查询副作用、正式同步入口、主机校验和 |
| 关闭 | 原创建方/主机回执、部分启动痕迹、当前实际存活状态 |

`startup_diagnostics.py` 汇总启动阶段；业务、运行条件和清理结果分别保留。缺失launch.json不代表进程从未启动。

## 大图载图前断开

先区分文件握手与地图业务问题。已确认的兼容插件可能把大小报告为0x7fffff及对应前缀CRC；只对认识的插件在本会话调整主机视图，保留原始值，地图完整字节不变。未经证据不要截断地图、删除资源或重复初始化插件。

## 窗口与条件

原生消息成功只说明分发。最小化不一定立即转移前台身份；使用独立采样检查IsIconic、前台归属、未知查询与窗口丢失。空前台HWND和非空HWND的PID查询失败是不同状态。

失焦或锁屏问题不通过反复激活其他应用解决；已验证的LAN后台能力也不代表锁屏可启动。

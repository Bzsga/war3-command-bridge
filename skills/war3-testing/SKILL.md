# War3 快速测试与验证

## 适用范围与入口

用于实际验证 Warcraft III 地图行为、复现游戏内问题或检查地图交付。以当前项目最近的 `AGENTS.md`、源码/构建入口、目标地图版本及用户反馈为准；已有项目门禁照常执行。纯 JASS 语义分析由 `war3-jass-engineering` 负责；独立模型、贴图产物沿用所属领域技能的验证流程。

按改动选取必要检查，不因加载本技能完整通关、解包所有资源、启动编辑器或建设测试框架。

## 缩短到达待测内容的时间

后期章节、波次、Boss 或成长后才能使用的系统，优先使用已有调试入口或临时测试版定点验证，不默认每轮从开局完整游玩。

1. **准备真实状态**：直接进入目标阶段，设置有代表性的等级、装备、队伍、任务和奖励状态；执行必要初始化与前置状态建立，不能仅生成目标单位而遗漏依赖。多人问题使用对应的客户端/玩家条件，单机通过不能证明同步正确。
2. **复用正式逻辑**：测试版与主项目使用同一套业务源码与资源；临时差异限于快速入口、状态准备和必要观测，不复制一套测试专用战斗、技能或奖励逻辑。优先复用已有入口，不为简单改动额外建设测试框架。
3. **针对性验证**：明确输入/触发条件、预期和通过判据；先检查本次改动的正常路径，再覆盖与改动相关的失败、死亡、取消、重复触发或同步边界，不增加无关全流程测试。
4. **检查阶段衔接**：对依赖前置流程的内容，检查从上一阶段正常进入目标阶段的初始化、状态传递和结算；定点测试不能替代受影响的衔接验证。
5. **合入正式改动**：必要检查通过后，将已验证的正式逻辑合入主项目，排除临时入口、作弊设置和测试状态，确认正式构建采用同一份逻辑，保留相应编译与打包检查。未能执行的运行检查明确列为待验，不表述为通过。

助手负责快速复现、针对性验证与相关回归；完整通关主要用于阶段性验收，用户通过正常试玩反馈长期体验、难度与构筑节奏，发现问题后继续修复。

## 按改动选择检查

- GUI 定义、物编字段和 native 签名以当前定义与编译链为准：分别回查 `ydwe-gui-three-piece`、`war3-object-editor`、`war3-jass-engineering`；不能省略导致解析或编译失败的字段，也不能用历史记忆替代签名核查。
- 用户负责实机验收的 War3 UI/表现调整，文字、配色、尺寸、图标与特效只做必要基本检查，不默认制作模拟预览、安排盲审或增加只断言函数存在/参数相同的测试。合成、扣费、物品继承、传送条件、爬塔流程、多人同步等行为仍做针对性测试，无需删除已有有用回归。
- 地图交付保留与产物有关的编译、资源存在性、GUI 字符串限制与打包完整性检查；终包路径及脚本同步等细节回查 [KKWE 离线打包验收](../kkwe/SKILL.md#离线打包验收)。
- 性能、缓存和并发实验保留基准与相关回归；mock 与实现共用的关键假设需有独立依据，不能循环证明。

没有常规测试框架时，使用与目标相符的可观察验证：

| 目标 | 可用证据 |
|---|---|
| 行为观测 | `BJDebugMsg` / `DisplayTextToPlayer` 配合实际状态、数值或对象变化 |
| 运行用例 | 指定玩家、触发器、单位和目标场景的游戏内实测 |
| 数值规则 | 项目已有的离线模拟，如 `sim_*.py` |
| 静态检查 | YDWE 自检、PJASS/JassHelper、`validate_triggers` |
| 数据与终包 | w3x2lni 解析、目标内部文件回读和源数据对照 |

日志输出、进程存在、文件存在或编译成功都不能替代目标行为通过的证据。

## 多轮命令式回归

默认通过 KKWE 本机 LAN 运行自动行为测试，使计时器与游戏逻辑在后台继续推进，无需保持焦点。单机 `-loadfile` 仅用于交互查看、启动诊断或明确的单机对照；画面/输入验证与后台业务验证分开安排，不通过反复激活窗口维持自动回归。具体启动与进程归属沿下述地图测试通道。

要减少重复启动和场景到达时间时，使用[定点场景与有限批次](references/bridge-batches.md)：共享标准库运行器，项目提供自己的正式逻辑适配器；相关场景可有意连续共享状态，不使用未验证的全局重置。运行器默认finally关闭所属游戏/host，本入口只接入已有会话，不新增地图/启动许可。

已有测试桥或需要反复准备、执行、读取和重置场景时，优先复用固定操作接口；普通定点测试仍用现有调试入口，不为每张地图新建框架。KKWE Lua/JASS 通道、会话文件、LAN 启动、窗口参数与进程归属统一回查 [地图测试通道](../kkwe/references/map-testing.md)。

- **游戏线程与真实逻辑**：外部客户端只发布固定命令，游戏内计时器读取后调用项目正式逻辑；不接受任意远程脚本。独立演示场景只证明接口可用，接入项目时须保留其正常初始化链，并定义自己的准备、观测和重置。
- **证明输入造成变化**：攻击等操作先建立未执行状态，再发真实命令，观察中间状态与最终事件。暂停单位仍可能自然回血，不能把生命完全不变当作通用断言；自定义击杀奖励须处理原生赏金，避免奖励叠加。
- **重复与隔离**：请求带 session/build 和唯一编号；相同编号/内容去重，同编号不同内容拒绝。超时后等待未完成响应或用原编号重试，不覆盖仍在途的请求；同一游戏中的新回归批次使用新编号前缀。
- **生命周期**：重复场景同时检查单位枚举、句柄清空、活动触发器数量及创建/销毁平衡；只看死亡次数或一次 reset 成功不足以证明没有累积。对非法请求、旧会话、超时等相关错误验证后续仍可响应。
- **测试收尾**：命令桥一批验证结束后默认及时关闭本会话拥有的War3和LAN主机，包括失败退出；用创建方保留句柄或已验证的会话shutdown，并检查回执。只有用户明确要求继续观看/交互时才保留。单条请求不算整批结束；不按进程名批量杀进程，不代关编辑器，不关闭其他会话。
- **后台条件独立判定**：记录前台 PID、最小化状态、采样间隔/最大间隙、游戏时钟推进及业务结果。中途进入前台的批次可以保留其业务证据，但不能算作全程后台通过；普通窗口后台、最小化、锁屏、无桌面和多人是不同条件。
- **测量边界**：分开记录启动到真正就绪、请求发布到匹配响应的中位数/P95、实际战斗等待；说明是否包含构建和解释器启动。后台游戏时钟可能慢于墙钟，不能把低通信延迟推定为同速模拟或热重载。

每轮持久化结果，保留失败批次与最终成功批次的独立身份。代码/环境或目标条件改变时做相关代表验证；已有有效证据可复用，不因经验沉淀再次启动游戏或重复完整矩阵。

## 工具与权限

- 工具选择与预检按 [kkwe-tooling](../kkwe-tooling/SKILL.md)；复用项目已有入口和有效预检，不绕过门禁。
- 实际启动、载图证据或运行版本不符时，按需读取 [KKWE 地图测试通道](../kkwe/references/map-testing.md)。独立启动测试已保存的磁盘版本，不保存编辑器内容、不重编译未打包源码。
- 授权统一按 [coding-discipline 的地图与启动权限](../coding-discipline/SKILL.md#地图与启动权限)。本技能不新增地图生成/写入、保存、覆盖、删除或编辑器启动许可；临时地图同样受该边界约束，沿用当前任务已经覆盖的许可，不重复申请。

## 报告实际验证范围

复用其他项目证据前，分开核对“桥/启动器能力”和“目标地图业务”：独立场景的LAN最小化攻击、结算与重置实测可以证明该环境下通道可工作，不能直接宣布当前地图最小化业务通过，也不应笼统说所有War3最小化都未验证。双开窗口或两份播放器不等于多客户端同步；接入实例/玩家通信前须核对本地文件、会话、原生进程身份是否隔离。按已有结果的环境、场景、输入和条件复用，进行中的修复不作完成证据；具体来源和历史指标留在项目证据文档。

分别说明源生成、静态/编译、终包回读、定点实机、衔接实机及未覆盖的体验部分。运行证据对应实际启动的地图路径与版本、输入条件、预期及观测；只完成其中部分时据实报告，不将快速测试通过表述为完整流程已验证。

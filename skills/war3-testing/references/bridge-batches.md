# 命令桥定点场景与有限批次

用于已有可靠命令桥，需要减少重复启动、等待到达目标内容或手工核对状态时。一般定点测试沿用现有调试入口，不默认建设新框架；本入口不写图、不启动游戏、不新增操作许可。

## 结构与边界

- 通用运行器负责有限用例列表、逐项报告、失败证据及finally关闭所属游戏/host；项目适配器负责正式业务入口、观测字段、固定预置和正确性断言。项目按钮/状态/路径不写入共享技能。
- 可以把相关场景组成连续批次，例如先自然结算，再交易，再检查刚获得内容的继承；明确共享状态是有意的。需要独立场景时，先证明局部重置覆盖全部依赖，否则重新启动。不要承诺任意世界快照或未经验证的全局重置。
- 准备只能是固定、受限的测试前置条件，保留正常初始化与正式逻辑；接口检查会话、场景序号、阶段、有效玩家和战斗状态，拒绝重复/过时准备。预置金钱、生命或跳过中间阶段要在报告标注，不能声称自然获取或通关。
- 根据变更选择已有相关用例；共享基础或跨系统改动保留相应完整回归。仅输入/工具链/内容相同才复用编译证据，不为提速刷新旧哈希或省略必要第一次运行证明。
- 用前后状态、原生对象/资源变化及异步结算断言。分发成功不是业务成功；重复请求不能再次扣费/领奖/进化。失败报告记录当前用例、最近请求及最后状态，保留前提不成立和业务失败的区别。
- 两步操作须等下一步真实可用（例如选卡后确认按钮启用），再发后续命令；不能用固定睡眠代替状态等待，也不能让即时执行的替身掩盖真实界面刷新时序。批次报告引用前置冒烟报告，便于复查自然流程证据。
- 每批结束或失败即关闭本会话游戏及host并检查回执，明确留看才keep-open。先正常流程后边界，按目标验证；行为测试不替代视听、真实点击或多人。

## 可复用入口

`scripts/run_bridge_batch.py`是标准库运行器，只接入已获授权启动的会话；无需地图工程目录布局或固定客户端路径。项目适配器是可信的本地工程源码，外部JSON仍只能请求固定业务操作，不允许远程任意脚本。

```powershell
python -X utf8 -B <本技能目录>/scripts/run_bridge_batch.py --adapter <项目适配器.py> --session <已启动会话.json> --cases <有限用例名...> --out <新报告目录>
```

适配器提供：

| 成员 | 契约 |
|---|---|
| `BOUNDARY` | 简述正常流程、预置与未覆盖条件 |
| `CASES` | 用例名到函数的有限映射，函数接收context；顺序/依赖由项目约定 |
| `open_context(session_path, report, persist)` | 校验会话/构建身份，构造客户端；不能另启动产品 |
| 用例函数 | 调用正式入口并进行断言；有超时/有限循环；更新report.checks和trace并persist |
| context.finish（可选） | 完成只读前台采样等观测，返回实际条件证据；不要在此编造后台通过 |
| `shutdown(session_path)` | 只关闭有归属的会话，返回包含ok的回执；即使open_context失败也能处理本次有效创建记录 |

运行器报告`report.json`，按场景记录通过、耗时、完整输入/结果及失败位置，分开保存收尾回执。cleanup失败不能报整批完全通过。参数或重复输出目录在接入前拒绝，不覆盖旧证据。keep-open只用于已有明确留看授权。

## 最小验证

1. 运行器用替身验证成功、用例失败、接入失败和shutdown失败：是否只关闭一次、报告是否忠实、keep-open是否明确。
2. 适配器先检查类型/编译，并用现有正式逻辑回归验证预置约束及断言；原生替身不足以证明实际对象继承。
3. 在同一真实游戏会话完成代表批次，证明准备→正式操作→实际结算，以及批后关闭。后台另采样，多人另实测。
4. 比较完整批次的启动次数与耗时，标明是否包含编译/打包/载图。共用一次启动的节省可作估计，但不能把估计说成实测加速倍数。

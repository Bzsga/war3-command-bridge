# 命令桥定点场景与有限批次

用于已有可靠命令桥，需要减少重复启动、等待到达目标内容或手工核对状态时。一般定点测试沿用现有调试入口，不默认建设新框架；本入口不写图、不启动游戏、不新增操作许可。

## 结构与边界

- 通用运行器负责有限用例列表、逐项报告、失败证据及finally关闭所属游戏/host；项目适配器负责正式业务入口、观测字段、固定预置和正确性断言。项目按钮/状态/路径不写入共享技能。
- 可以把相关场景组成连续批次，例如先自然结算，再交易，再检查刚获得内容的继承；明确共享状态是有意的。需要独立场景时，先证明局部重置覆盖全部依赖，否则重新启动。不要承诺任意世界快照或未经验证的全局重置。
- 准备只能是固定、受限的测试前置条件，保留正常初始化与正式逻辑；接口检查会话、场景序号、阶段、有效玩家和战斗状态，拒绝重复/过时准备。预置金钱、生命或跳过中间阶段要在报告标注，不能声称自然获取或通关。
- 根据变更选择已有相关用例；共享基础或跨系统改动保留相应完整回归。仅输入/工具链/内容相同才复用编译证据，不为提速刷新旧哈希或省略必要第一次运行证明。
- 用前后状态、原生对象/资源变化及异步结算断言。分发成功不是业务成功；重复请求不能再次扣费/领奖/进化。失败报告记录当前用例、最近请求及最后状态，保留前提不成立和业务失败的区别。
- 两步操作须等下一步真实可用（例如选卡后确认按钮启用），再发后续命令；不能用固定睡眠代替状态等待，也不能让即时执行的替身掩盖真实界面刷新时序。批次报告引用前置冒烟报告，便于复查自然流程证据。
- 新组件有冷启动或伴随进程时，核对无缓存/请求目录的初始化与本局第一条命令，不能只靠已有缓存证明可用。用会话世代及真实绑定的游戏PID识别旧请求/退出，不能以固定短时间阈值丢弃本局冷启动命令，也不能把长寿命编辑器/启动者仍在当作游戏仍在；替身退出验证与真实War3运行分别报告。
- 每批结束或失败即关闭本会话游戏及host并检查回执，明确留看才keep-open。先正常流程后边界，按目标验证；行为测试不替代视听、真实点击或多人。

## 可复用入口

`scripts/run_bridge_batch.py`是标准库运行器，只接入已获授权启动的会话；无需地图工程目录布局或固定客户端路径。项目适配器是可信的本地工程源码，外部JSON仍只能请求固定业务操作，不允许远程任意脚本。

```powershell
python -X utf8 -B <本技能目录>/scripts/run_bridge_batch.py --adapter <项目适配器.py> --session <已启动会话.json> --cases <有限用例名...> --out <新报告目录>
```

适配器提供：

| 成员 | 契约 |
|---|---|
| `BOUNDARY` | 简述正常流程、预置与未覆盖条件 |
| `CASES` | 用例名到函数的有限映射，函数接收context；顺序/依赖由项目约定 |
| `open_context(session_path, report, persist)` | 校验会话/构建身份，构造客户端；不能另启动产品 |
| 用例函数 | 调用正式入口并进行断言；有超时/有限循环；更新report.checks和trace并persist |
| context.finish（可选） | 完成只读前台采样等观测，返回实际条件证据；不要在此编造后台通过 |
| `shutdown(session_path)` | 只关闭有归属的会话，返回包含ok的回执；即使open_context失败也能处理本次有效创建记录 |

运行器报告`report.json`，按场景记录通过、耗时、完整输入/结果及失败位置，分开保存收尾回执。cleanup失败不能报整批完全通过。参数或重复输出目录在接入前拒绝，不覆盖旧证据。keep-open只用于已有明确留看授权。

使用 `scripts/session_lifecycle.py` 在预检、准备创建产品和匹配就绪时分别持久化preflight/starting/ready，校验session/build且不允许阶段倒退。只有明确的本会话preflight记录且没有主机监督器、客户端身份、握手或启动结果等矛盾证据，才能返回 `cleanup_status=not_started`；仅缺少launch.json不能据此跳过关闭。已启动或归属不明仍交原创建方关闭。保留业务失败，区分preflight/startup/attach/case/observation/cleanup阶段；业务通过但清理失败不能算整批通过，明确留看是retained。`scripts/check_lifecycle.py`可只用临时证据和替身验证这些分支，不启动地图。

## 最小验证

LAN自动入房是独立的启动阶段：某些KKWE loader通过菜单按键进入LAN，普通窗口后台的地图计时器通过不证明锁屏时能够启动。可复用 `scripts/desktop_probe.py` 只读检查可访问的Default输入桌面及锁屏前台，启动前拒绝不可交互条件；启动期间记录桌面变化、所属游戏进程和宿主入房/载图阶段。不得自动解锁、切桌面或激活用户其他应用；已授权的所属游戏/创建方测试窗口按固定消息通道操作。没有记录的旧失败不能追认为锁屏所致；端口、网络或环境假设须做受控对照，排除的临时实验不进入默认入口。

最小化条件须独立采样：`IsIconic` 为真并不保证 `GetForegroundWindow` 已转移。无需用户手动切窗口的测试，可由已授权的原生启动者将焦点转到它自己创建的测试窗口，限定只操作所属游戏与自身窗口，并在 `finally` 销毁；不要激活用户其他应用。严格通过需保留最小化、前台归属、PID查询失败、窗口丢失及采样间隔证据。前台 HWND 为零表示当时无前台窗口，非零 HWND 查询 PID 失败才是未知；未知不能当作后台通过。窗口消息回执不代替入房、载图和会话握手，未验证的锁屏或多人条件另列。

同机多个War3项目不能同时使用无会话筛选的自动入房。只检查已有War3会漏掉其他ydhost和检查后同时启动的竞争；复用 `scripts/lan_startup_guard.py`，以游戏安装根下同一个WBTestBridge/lan-startup.lock序列化预检→主机创建→游戏启动→匹配握手。锁内检查本机War3/ydhost，发现其他测试即拒绝且保留其身份，不关闭它们。握手后由活动进程检查保护持续占用，失败释放租约；参与项目都须遵守同一入口。远端LAN房间或不遵守入口的启动器仍可能竞争，不能宣称全局网络隔离。

多网卡默认广播发现仍不可靠时，可接入 `scripts/lan_discovery.py`：客户端未启动时独占UDP6112捕获本会话宿主GAMEINFO，校验协议长度、精确房间名与真实监听端口；先关闭捕获socket，再仅向127.0.0.1重发验证过的房间信息，匹配握手后停止。不能共享客户端接收socket、重放其他房间或无限发送。保留广播来源、发送次数、实际host.log回环加入和收尾证据；这绕开广播路径，不据此断言具体驱动丢包根因。它仍依赖兼容loader自动入房，不证明锁屏启动或远端多人。

Lua 从共享 JASS 计时器回调进入时，避免按每个本地请求嵌套 `jass.common.ExecuteFunc` 创建执行上下文；优先读取 `jass.globals` 与只读 native，固定业务入口使用当前安装提供的 `jass.code` 直接调用。迁移前确认组件支持并实际编译/运行，不能按接口名称推断同步安全。局部查询不得创建/销毁单位、物品、group、timer、trigger 或推进随机源；需要这些操作的查询改为同步域更新缓存，本地只读取缓存。重复/不同客户端查询数量可以不同，不能让查询改变世界或句柄分配。

多人运行必须独立检查主机的实际不同步/校验和告警；双方可见状态相同不等于引擎同步。客户端自己的发送序号不要求跨端相同，重复请求应比较各客户端自己的前后值。用无命令、模块加载但不轮询、空计时器/纯求值/空闲轮询等受控对照定位桥引入的影响；只有新增失败才开展这些诊断，不默认每个项目重复整套对照。

Lua 构造快照需遵守实际 JSON 编码器的数组标记；JASS 未分配的数组单元可能通过 Lua 暴露为 nil，应按原字段语义保留零值。响应编码也放入保护范围，失败返回带请求身份的错误回执，不能让调用者只看到超时。业务是否已经执行与响应是否编码成功分开记录，重试仍须按请求 ID 去重。

1. 运行器用替身验证成功、用例失败、接入失败和shutdown失败：是否只关闭一次、报告是否忠实、keep-open是否明确。
2. 适配器先检查类型/编译，并用现有正式逻辑回归验证预置约束及断言；原生替身不足以证明实际对象继承。
3. 在同一真实游戏会话完成代表批次，证明准备→正式操作→实际结算，以及批后关闭。后台另采样，多人另实测。
4. 比较完整批次的启动次数与耗时，标明是否包含编译/打包/载图。共用一次启动的节省可作估计，但不能把估计说成实测加速倍数。

# 独立视觉审查

受审候选：outputs/war3-test-workbench/workbench/ui.py；work/ui-captures 六张截图（console、console-small、project、wizard、cases、reports）。只读截图与源码，未操作应用、未启动游戏；数字只作示例状态。

## 第一印象与完成度
深色工具气质统一，标题、导航选中态和青绿色主要操作有稳定层级。1300×850 页面留白充足，980×660 的测试台在隐藏 AI 后仍能辨认三列、顶端操作和日志，未见文字或按钮溢出。五页面与作者定义命令、用例的目标匹配，常用按钮多数紧凑并排。整体适合作为开发工具；表单和空状态的易读性仍有局部不足。

## 明确缺陷
1. 接入向导底部三项许可复选框，未选框几乎与背景融为一体，难以看出这是可勾选控件。wizard.png 左下 x≈198、y≈688/718/748；ui.py:34 仅设置 spacing，没有为 indicator 设置高对比边框。建议显式定义未选和已选 indicator。当前截图不证明已选态。
2. 测试用例页“编辑命令与状态目录”占满内容区一整行（cases.png x≈198–972，y≈776），与用户“按钮紧凑并排”要求不符，也与相邻工具栏不一致。ui.py:345 直接加入 QVBoxLayout。建议并入紧凑按钮栏或另设靠左按钮行。
3. 项目已显示 SOURCE 接入示例且日志已打开项目，但底部仍写“尚未打开项目”（console.png、project.png 及其他页底部）。这是可见状态自相矛盾。ui.py:72 写入初始状态，158–164 open_project 未更新 statusBar。建议打开项目时刷新为当前项目名/运行状态。
4. 测试台整数输入的增减按钮边界与箭头十分暗，几乎不可辨（console.png x≈613–626、y≈195–230；console-small.png x≈604–617）。ui.py:26 沿用暗色 Fusion 控件但未定义 spin subcontrol 对比。数字本身清楚，键入仍可识别；建议定义 up/down-button/arrow 的可见样式。

## 设计取舍与非阻断建议
- 项目页将地图路径、JSON 构建入口和模型凭据放在一张表单，利于熟练用户快速配置；对 GUI 作者，JSON 入口的长串可读性弱且缺少“源码工程可选/适用”提示。单行长路径正常会横向滚动，当前截图不足以判为溢出缺陷。
- 用例编辑器直接显示声明式 JSON，给作者最大自由，但 GUI 作者学习成本明显高。可加一条最小示例/格式帮助入口，不应假定必须改成可视化编辑器。
- 测试报告页当前左右两个空白大区没有空状态提示，难区分“暂无报告”与“未读取”。建议加短占位文字；空截图本身不证明加载失败。
- AI 面板纵向占满，主要操作在上、分析输出在中、辅助操作在底，层级合理；全宽侧栏操作在其窄专用列里可以接受，与内容区跨 774 px 的单按钮不同。

# War3 地图测试工作台 0.1

中文 Windows 桌面工具：导入已保存地图，接入专用测试副本，使用固定命令与自动化用例进行真实行为回归。命令、状态、测试目标与标签由每张地图自行定义，不预设商店、战斗或关卡分组。

## 启动

解压完整桌面包，双击 `War3TestWorkbench.exe`。保留同目录 `_internal`；无需安装 Python。运行地图需要自己安装的 War3 1.27a、兼容 KKWE 和编译组件；第一版为单客户端本机 LAN。

1. 在“项目”页填写已保存地图、KKWE 安装根目录和游戏根目录，新建项目。
2. “接入向导”检查环境并读取地图。源码工程可登记构建入口；GUI 地图需有 WTG/WCT 和匹配定义。
3. 要使用 AI，保存自己的 DeepSeek Base URL、模型名和 API_KEY，测试连接。模型名按服务当前实际可用名称填写。
4. 描述测试目标，核对将发送的源码范围，允许发送相关片段后生成接入方案。
5. 审阅命令、状态和判据，勾选创建测试副本与启动所属游戏，执行接入验证。
6. 在测试台手动操作，或在用例页编辑命令／等待／断言，运行选中用例或全部用例。

已有命令目录和用例时，第3、4步可省略；关闭模型连接后仍可运行。自动测试结束或失败会关闭所属游戏和主机；手动会话用“停止”关闭。关闭程序会先收尾。

## 先试演示

选择自己安装中的**独立演示模板**，完成环境配置后，用顶部“从独立模板创建演示”生成源码、GUI两个演示项目。打开对应目录中的 `project.json`，在接入向导允许测试副本和游戏启动，运行全部用例。

演示检查一个计数业务的正常、条件边界与同请求ID去重。这个业务只属于示例，工具没有内置该分类或判据。原模板不被覆盖；不把正式项目作为演示模板。模板需为W3I v25，含Player(0)真人槽。

## 接入边界

- 源码入口登记为JSON参数数组，程序用绝对路径，`{source}`为隔离源码副本，`{output}`为完整运行JASS输出。Lua工程可使用其已有构建链和JASS包装入口；本版不直接解析任意Lua框架内部对象。
- 固定命令支持已有JASS函数的integer/real/boolean/string参数，以及不依赖事件上下文的GUI触发器。GUI入口保留启用检查和正式条件，不直接绕过条件执行动作。
- 状态支持标量全局变量、固定索引标量数组、可选金币/木材和桥计时。没有现成可靠入口或观测字段时，AI报告缺口，不编造测试通过。
- 用例有命令、等待和断言，支持前后状态引用与数值差值。没有通用重置；前置和清理由地图自己的命令建立。用例按顺序共享会话。
- 同ID同内容只重放结果；不同ID的重复业务操作是另一类测试。超时表示结果未确认，使用“查询上次请求”，不能换ID重做未知结果的交易。
- 正式地图只读。改图后重新生成测试副本；不存在或签名变化的入口会报错。导出只含命令与用例，接收方重新配置环境并验证映射。

详见 [用例与接口](docs/INTERFACES.md)、[实际验证及限制](docs/VALIDATION.md)、[组件与许可](NOTICE.md)。

## 开发与命令行

```powershell
python -m pip install -r requirements-dev.txt
python main.py
python -m pytest tests -q
python build_release.py --method pyinstaller
# 原设计构建入口；需可用C编译器与Nuitka
python build_release.py --method pyside6-deploy
```

桌面包也支持无AI的脚本式回归，退出码0为通过，1为失败：

```powershell
.\War3TestWorkbench.exe --run "项目\project.json" --allow-map-copy --allow-game-launch --tag "作者自定义标签" --output "新报告目录"
```

`--case`可重复指定用例ID。按标签或ID过滤时，作者需同时选择所需前置用例。桌面“重跑失败用例”会保留列表顺序，并带上失败项之前的用例，避免默认丢弃依赖。

本次桌面包采用PyInstaller：pyside6-deploy的编译器下载在本环境停滞，官方构建入口保留，未把该构建路线标为通过。
